# 抽取语义边界

本文件指导 agent 在产出 `extract.json` 时**判断什么应该提取、归到哪里**。
所有判断基于语义；scanner 的 `keyword_hits` 只是注意力提示。

> **关键约束**：每条 evidence 的 `text_quote` 必须是其 locator 文本的
> **verbatim 子串**（按 `normalize_text` 比较），单条 ≤ 200 字符且不可
> 跨段落/跨单元格。

## 通用原则

1. **`废标项` 是重头戏，要兜底找全；其他类轻量处理**。废标项典型 15-40 条；
   其他类识别到 1-3 条代表性 evidence + 一行 summary 即可，没找到的就不
   出现在 `重点信息` 数组里。
2. **同义重复要全标**。同一硬性条款常在公告章 / 须知章 / 前附表 / 评分细则
   多处重复出现，只要确实是约束力条款，每个出现位置都引一条 evidence。
3. **前附表（locator 多为 `T1Rxx Cyy`）是硬性条款最密集的载体**。逐行扫
   一遍，对照 §1 废标项的五类逐项判断；其他类有明确条款再纳入。

---

## 1. 废标项（重头戏）

**任何会导致投标被否决/作废/拒绝/视为无效/不通过审查的硬性触发情形**都
属于本类，无论它出现在哪个章节、是否带"废标"二字。每条 evidence 必须带：

- `subtype`：五选一（见下文五个子标题）。
- `text_quote`：locator 原文 verbatim 子串，≤ 200 字，给标黄锚定。
- `key_point`：≤ 30 字动词短语，点出**触发情形本身**（不复读"将被视为
  无效"等结果句），表格"要点"列要一眼看懂。例 "未按要求递交保证金"、
  "★交货期超过 30 天"。引导句（"投标人有下列情形之一的"）写"总则：xxx"。

### subtype = `显式否决`

以"投标人有下列情形之一的，其投标将被否决/作废/拒绝/视为无效投标"等
领句引出的整组枚举。**领句一条 + 每个枚举项一条**。条款很长就拆成多条
evidence，每条对应一个独立触发情形。

### subtype = `资格审查`

资格审查表（也叫"资格性审查"）章节里的逐项审查标准。"未通过资格审查
的投标人，其投标作无效投标处理"等表述把这些项变成废标触发条件。

- 资格审查表的每行都是一个废标触发条件，**逐行各引一条 evidence**。
- 与"资质要求"类有重叠：同一条款（如"具备有效营业执照"）在 `重点信息.
  资质要求` 引一条作为门槛，在 `废标项` 引一条作为审查触发条件。**这是
  合规的双类共享，两边都要引**。

### subtype = `符合性审查`

符合性审查（也叫"响应性审查"）章节里的逐项审查标准。"未通过符合性审查
的投标，按无效投标处理"。逐行/逐项纳入。常见审查项：投标文件签字盖章 /
装订 / 密封 / 报价唯一性 / 投标有效期 / 主要技术参数响应等。

### subtype = `实质性条款`

文件里标注为 ★ / ▲ / "实质性条款" / "不允许负偏离" / "不响应即作废" 的
条款。这些往往散落在技术规格、商务要求章节，但语义等同于废标触发条件。

- 例："★交货期不得超过 30 天，否则按无效投标处理"。
- 例："投标人对带★条款的任何负偏离将被视为实质性偏离，作废标处理"。
- 评分细则里"实质性条款不响应直接废标"的总则也属本类。

### subtype = `散落`

全文搜读时，凡语义上写了"否则视为无效投标 / 否决其投标 / 不予受理 /
资格不合格 / 视同放弃"等约束句，即使单独出现在某个段落、不在显式废标
章节，也要纳入。

- 例："投标人未在规定时间到达开标现场的，视为放弃投标资格"。
- 例："报价超过最高限价的，作废标处理"。

### 排除

- "废标后重新组织采购"等程序性说明（这是结果，不是触发情形）。
- 评分扣分项（这是评分加减分），**除非**明确写了"扣至 0 分以下作废标处理"
  或"实质性偏离作废标处理"。
- 单纯的资格门槛陈述、没有审查触发语境的，不重复纳入；只在资格审查表
  那一处把它作为审查项纳入。

### evidence 数量参考

典型采购文件应在 **15-40 条**之间，覆盖前述五类 subtype。少于 10 条几乎
一定是只看了显式否决章节，遗漏了资格审查表、符合性审查表、★ 实质性条款。

### summary 写法

按 5 个 subtype 分子标题列出每条触发情形：
```
显式否决条款：①投标文件未加盖公章；②……
资格审查不通过：①未提供有效营业执照；②……
符合性审查不通过：①未按格式签字盖章；②……
实质性条款偏离：①★交货期超过 30 天；②……
其它无效情形：①开标现场未到场；②报价超最高限价；……
```

## 2. 重点信息（轻量提炼）

`重点信息` 是数组，每个 category 一个对象。**找到了就提取一条 summary
+ 1-3 条代表性 evidence；没找到就不出现**。不强求穷举、不强求覆盖。

下面给六个常用 category 的语义边界：

### category = `中标人数量`

**找什么**：本次采购最终选取几家入围/中标的明确数字或规则。
"拟入围 N 家"、"中标人数量：N 家"、"按报价排序确定前 N 名"等。

**排除**：参与门槛（"鼓励 N 家以上参与"）、联合体成员上限、评标委员会人数。

**summary**：一句话含数字。如"本项目入围 2 家供应商"。
**evidence**：通常 1 条；散落多处可 2 条。

### category = `时间节点`

**找什么**：对投标人有约束力的截止/开标时间——报名截止 / 投标递交截止 /
开标时间 / 开标地点 / 答疑截止。

**排除**：项目背景历史日期、合同履约期、服务期。投标有效期归 `其它硬性规定`。

**summary**：列表式，时间精确到分钟。
```
报名截止：2026-05-10 17:00
投标递交截止：2026-05-15 09:00
开标时间：2026-05-15 09:30
开标地点：XX 市公共资源交易中心 N 层 XX 厅
```
**evidence**：每条时间一条 evidence，方便人工逐条核对。

### category = `保证金`

**找什么**：投标保证金 / 履约保证金的金额、币种、缴纳方式、退还规则。

**排除**：只有标题没有金额的段落、纯法律性表述（"投标人应按规定缴纳"）。

**summary**：把金额、缴纳方式、退还规则各点出。
**evidence**：金额条款必须高亮（最关键）；缴纳方式、退还规则各 1 条。

### category = `资质要求`

**找什么**：投标人作为单位必须具备的硬性资格门槛——主体资质（营业执照）/
行业资质（许可证、等级）/ 财务能力 / 业绩 / 信誉（信用中国、失信被执行
人、裁判文书网）/ 不存在禁止情形 / 单位纳税社保良好记录。

**排除**：项目实施人员的个人资质（归 `人员社保证明`）、评分加分项里的
资质（这是评分不是门槛）。

**注意双类共享**：作为门槛要求在这里引一条，同一条款作为资格审查触发
条件还要在 `废标项.evidence` 里以 `subtype=资格审查` 再引一条。

**summary**：列出几大类门槛的核心要求。
**evidence**：1-3 条最具代表性的；不强求覆盖每一小项。

### category = `人员社保证明`

**找什么**：要求**项目实施人员**提供社保 / 公积金 / 劳动合同 / 个税缴纳
证明的硬性条款。

**排除**：单位整体的社会保障资金良好记录（那是 `资质要求` 的子项）。

**找的位置**：前附表"主要人员要求"行 / "其他要求证明材料"行 / 评分细则的
人员加分项前提条件。三处都没有再判定不存在。

**summary**：明确"谁、提供什么、覆盖什么周期"。
**evidence**：1-3 条交叉位置的代表性引用。

### category = `其它硬性规定`

**兜底**，只放确实不属于前 5 类的约束：
- 联合体投标 / 分包 / 转包 是否允许
- 投标有效期
- 报价上限（最高限价）
- 不接受备选方案 / 替代方案
- 必须现场递交 / 不接受电子标
- 中标后费用约束（招标代理服务费、平台使用费）

**注意分流**（这些不要误入本类）：
- 关联企业、信誉不良、不存在禁止情形 → 归 `资质要求`
- 已在 `废标项` 列出的触发情形 → 不重复

**summary**：分点列出，每点一句话。
**evidence**：4-6 条最重要的即可。

---

## 通用建议

- **某 category 没有找到时，从 `重点信息` 数组里整个略去**。不要塞空对象、
  不要写 `present=false`。
- **summary 是 agent 复述、text_quote 必须 verbatim**。前者服务可读性，
  后者服务可锚定，两者目的不同。
- **跨段落引用要拆**。一条 evidence 只能引一段/一格。
- **优先引用条款主干**而非引导句。"下列情形之一"作开头一条 evidence，
  每个枚举项才是真正的硬性内容。
